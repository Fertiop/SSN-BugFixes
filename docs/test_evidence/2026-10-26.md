### Какие симптомы первоначально воспроизводились

| ID | Результат исходного SSN | Результат с патчем |
|---|---|---|
| SSN-001 | Не сохраняется родительский `connectable` | Записывается и читается NBT |
| SSN-002 | `NullPointerException` из `getBlockState(null,...)` | Null-safe возврат |
| SSN-003 | Кабель по координате скрывает 7 алмазов более приоритетного кабеля | 7 видны, без двойного счёта |
| SSN-004 | Камень размещался без фактического списания | Отказ от бесплатной установки и корректная компенсация |
| SSN-005 | 8 бутылочек мёда -> 1 блок, 4 пустых бутылки, 4 пропавших неиспользованных | Баланс соблюдён при массовом крафте |
| SSN-006 | Плохой `IItemHandler` скрывает 7 алмазов хорошего сундука | Хорошее хранилище остаётся видимым |
| SSN-007 | `request(...,false)` возвращает фантомный камень после реального `EMPTY` | Возвращает `EMPTY` |

**Важная хронология:** первые тесты SSN-004/005 падали из-за ненастроенного fake player Netty channel. После исправления среды 005 дополнительно имел ложный подсчёт из `NetworkCraftingInventory.getItems()`; он исправлен на `getItem(slot)` + подсчёт dropped entities. По исправленным тестам доказаны настоящие проблемы. Первый вариант SSN-004 с одним переносом списания не прошёл: найден отдельный SSN-007 с возвратом simulated stack на неудачной реальной выдаче. После устранения обеих первопричин все тесты стали GREEN.

После указанного run четыре бывших optional теста сделаны required и усилено требование «ни одного optional failure». Новые GitHub Actions ещё должны подтвердить строгий режим.
